# MCP: когда что использовать

Каждый вызов MCP тратит токены: ответы, снапшоты, скриншоты. Сначала — локальные средства: код проекта и типы в `node_modules`, поиск по репозиторию, `npm run lint` / `typecheck` / `build`. MCP — только в ситуациях из таблицы, по одному серверу на задачу.

| Ситуация | Сервер |
| --- | --- |
| Нужен актуальный API библиотеки или конкретной версии | Context7 |
| Перед коммитом или релизом | Playwright |
| Что-то сломалось (консоль, сеть, вёрстка, скорость) | Chrome DevTools |
| Задача про GitHub: PR, issues, Actions, удалённый репозиторий | GitHub |

## Context7

- Только если API не видно в коде и типах из `node_modules` или новая версия могла изменить поведение.
- Известные ID — сразу `query-docs`, без `resolve-library-id`: Next.js `/vercel/next.js`, React `/reactjs/react.dev`, Tailwind CSS `/tailwindlabs/tailwindcss.com`, lucide `/lucide-icons/lucide`. Версию из `package.json` указывай в запросе.
- Один узкий вопрос на вызов (ответ ≈ 1–2 тыс. токенов). Одно и то же в рамках задачи не запрашивай повторно.

## Playwright

- Перед коммитом или релизом и после заметных изменений интерфейса: затронутые страницы, ошибки в консоли, ключевые сценарии, ширина 1440 и 390.
- Не после каждой мелкой правки и не для поиска причины ошибки (для этого — Chrome DevTools).
- Экономия: снапшот сохраняй в файл и ищи элементы через `browser_find`; несколько шагов объединяй в один `browser_run_code_unsafe`; скриншоты — jpeg в `.playwright-mcp/` и только для визуальной проверки. После проверки закрой браузер и удали временные файлы.

## Chrome DevTools

- Когда что-то сломалось: ошибка в консоли, упавший запрос, неверные стили, просадка производительности. Нашёл проблему через Playwright — разбирай причину здесь, проверку не дублируй.
- От дешёвого к дорогому: `list_console_messages`, `list_network_requests` → `get_console_message`, `get_network_request`, `get_css_styles`, `evaluate_script` → `take_snapshot` → `take_screenshot` → `performance_start_trace`, `lighthouse_audit` (только для вопросов скорости).

## GitHub

- Только когда задача связана с GitHub. Локальные коммиты, ветки и diff — через `git`, не через MCP.
- По умолчанию сервер выключен (`"disabled": true` в `.kiro/settings/mcp.json`). Нужен — попроси пользователя включить его в панели MCP, по окончании — выключить.
- Списки запрашивай с фильтрами и небольшим `perPage`. Перед изменением (PR, issue, merge) прочитай текущее состояние.
