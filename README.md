# IDELUXE STUDIO V5

Новая версия сайта платформы монтажёра IDELUXE (IDELUXE — никнейм одного человека, не школа и не команда). Сейчас здесь готовы лендинг, тарифы и аккаунты: стиль, видео, окно редактора и плеер шоурила перенесены из v4, космический фон (звёзды и планета) и 3D-декор сделаны заново. Структура сделана заново, под рост проекта.

Стек: Next.js 16 (App Router, Turbopack) · React 19 · Tailwind CSS 4 · TypeScript 5.9 · lucide-react · Better Auth на SQLite (`node:sqlite`, нужен Node 22.5+) · nodemailer.

## Быстрый старт

```bash
npm install
Copy-Item .env.example .env.local   # bash: cp .env.example .env.local
npm run dev                         # http://localhost:3000
```

Без ключей всё работает: ИИ-ассистент отвечает подсказкой о настройке, регистрация и вход по email работают сразу (база `data/ideluxe.sqlite` создастся при первом запросе, таблицы — сами). Кнопки Telegram и Google без своих ключей объясняют, что способ не подключён. Пока не задан SMTP, подтверждения адреса нет и аккаунт входит сразу после регистрации. `BETTER_AUTH_SECRET` локально можно не задавать, в продакшене он обязателен.

Проверки: `npm run lint`, `npm run typecheck` (сам генерирует типы маршрутов), `npm run build`. `npm run check` = lint + typecheck.

Правила, которые держат структуру:

- Пути страниц и якоря лендинга — только из `config/routes.ts`, меню и футер — из `config/navigation.ts`. Строк вида `"/pricing"` в компонентах нет.
- Тексты, цифры пака, FAQ, контакты правятся в `content/*` и `config/site.ts`. Ассистент читает те же файлы, поэтому его ответы совпадают с сайтом.
- Фича импортируется снаружи через свой `index.ts`. Серверные файлы (`*.server.ts`, `system-prompt.ts`, `lib/server/*`) помечены `import "server-only"`: сборка упадёт, если их подтянет клиентский компонент.
- Цвета, шрифты и анимации — токены в `styles/tokens.css`. Классы `glass`, `btn-*`, `section`, `reveal` и т. д. — в `styles/components.css` и `styles/effects.css`.
- Палитра «Eclipse»: холодный графитовый чёрный, тёплый айвори для текста и один сдержанный акцент — шампань (`accent`). Цвет в основном даёт «фотографичный» фон (голубая атмосфера, золотой рассвет за планетой), интерфейс почти монохромный, главные кнопки айвори с тёмным текстом. Полупрозрачные оттенки в CSS и произвольных значениях Tailwind пишутся через RGB-каналы из `tokens.css`: `rgb(var(--rgb-accent) / 0.3)`. Каналы и `@theme` держи одинаковыми. Цвета планеты — в `PLANET_FRAG`, звёзд — в `starfield.ts`.
- Подписи читаются. Мелкие подписи набираются основным шрифтом нормальным регистром: `eyebrow` — плашка над заголовком страницы, `kicker` — тёплая строка с ромбиком над крупным заголовком карточки, `label` — название плитки, списка или группы ссылок (`styles/components.css`). Заголовок карточки — `font-display text-[15px] font-semibold`. Мелкие разреженные капсы моноширинным шрифтом остались только у «редакторских» меток: COMP и таймкоды заголовков разделов, прелоадер, окно редактора. Самый тусклый текст — `text-dim` (контраст ≈5,7:1), бледнее для текста не делай.
- Стекло (`glass`) как у шапки в развёрнутом виде наверху страницы: лёгкая тёмная заливка поверх сильного размытия, светлее плавающей шапки. `glass-strong` (плотнее) — только для панелей поверх текста, сейчас это ассистент. Два правила, иначе размытие пропадает:
  - в CSS пиши только `backdrop-filter` без `-webkit-` (префикс для Safari добавит сборка; если написать оба, Chrome остаётся без размытия);
  - `reveal` и другие эффекты с прозрачностью или фильтром вешай на саму карточку, а не на её обёртку.

### Как добавить

- **Блок лендинга**: `features/landing/sections/<name>/<name>-section.tsx` с классом `section`, при необходимости id из `landingAnchors` и пункт в `mainNav`. Подключить в `landing-page.tsx`. Заголовок — `SectionHeading` (метка `COMP 0N`, таймкод, под заголовком контурное «IDX»; другое слово — `ghost`, без него — `ghost={false}`).
- **Первый экран**: на десктопе заголовок, подзаголовок в одну строку, окно редактора и цифры пака помещаются в экран целиком, наверху страницы (туда ведут «Главная» и логотип). Окно шириной с ряд цифр. От высоты экрана зависит только ширина монитора программы (`--editor-monitor` в `hero-section.tsx`), боковые панели забирают остальное (`vfx-view.tsx`). На экранах до 1200 px высотой (вариант `short:` из `styles/tokens.css`) редактор компактнее: без корзины проекта, очереди экспорта и дорожки A2, боковые панели высотой с монитор. Если добавляешь что-то в первый экран, проверь 1440×900 и 1536×864.
- **Окно редактора** (`features/landing/sections/hero/editor`): в заголовке окна две вкладки — «Шоурил VFX» (`vfx-view.tsx`, шоурил в мониторе и его таймлайн) и «Шоурил эдитов» (`edits-view.tsx`, лента вертикальных эдитов). Переключение — клик или ←/→ на вкладках: панели плавно сменяются со сдвигом в сторону вкладки, по окну пробегает полоса света (`editor.css`). Вкладка VFX задаёт высоту окна, эдиты лежат поверх неё той же высоты, так что первый экран не прыгает. Пока открыта одна вкладка, видео и часы другой стоят.
- **Появление блоков страницы**: класс `arrive`, порядок — `[--i:N]`. После перехода, при котором летит камера, блоки появляются вместе с ней (см. «Космический фон»). Вешай на саму стеклянную карточку, а не на обёртку: анимация прозрачности или фильтра на родителе отключает размытие стекла внутри.
- **Переходы между страницами** (`features/transitions`): клик по внутренней ссылке сначала плавно уводит видимые блоки текущей страницы (≈0,3 с, ease-in), камера при этом уже летит, потом открывается новая страница. Назад/вперёд, новые вкладки, якоря на той же странице и «Уменьшить движение» работают как обычно. Отключить для ссылки — `data-no-transition`.
- **Тяжёлая работа на время перехода** (`lib/transit-hold.ts`, на `<html>` — `data-transit`): с клика и до посадки блоков новой страницы стоят фоновые видео, часы и скопы редактора, бесконечные анимации первого экрана (покачивание 3D-декора, кольца платформы, подсказка на мониторе; атрибут `data-loop` для инлайн-анимаций). Уходя со страницы, всё останавливается сразу, на новой стартует после появления. Счётчики цифр никого не ждут: каждый стартует, как только его карточка начинает появляться (событие `animationstart` её `.arrive`), так же и после прелоадера. Блоки лендинга ниже первого экрана после перехода строятся после посадки (`features/landing/after-arrival.tsx`), но сразу, если посетитель к ним направился: ссылка на блок в меню (`HashLink` → `lib/deferred-blocks.ts`, прокрутит, как только блок появится), колесо, свайп, клавиши прокрутки. Переход к якорю с другой страницы («Обо мне» с «Тарифов») строит их сразу. Новое тяжёлое на первом экране подключай к этому сигналу. На `<html>` не вешай селекторы со `*` и наследуемые свойства, которые меняются во время перехода: каждое такое изменение пересчитывает стили всей страницы прямо посреди полёта.
- **Знак IDX**: вектор `IDX_MARK` в `components/icons.tsx` (`LogoMark`, контуры для прелоадера) и `app/icon.svg` (фавиконка), держи их одинаковыми. Нарисован по мотивам оригинала `assets/brand/idx-icon.png` (у него стеклянные детали, на размерах логотипа они превращаются в кашу): плоские формы на сетке 32 с толщиной штрихов 4–5 единиц, читается от 16 px, на тёмном и на светлом фоне. Растровые копии (`app/icon.png` — запасная фавиконка, `app/apple-icon.png` — iOS) после правки знака: `npm run brand --prefix tools/decor-render`.
- **Страницу**: путь в `config/routes.ts`, файл `app/<path>/page.tsx`, при публичной странице — строка в `app/sitemap.ts`. Для заглушки есть `ComingSoon`.
- **Новую фичу**: папка `features/<name>/` со своим `index.ts`.
- **Страницу только для своих**: на сервере `const viewer = await getViewer()` (`lib/server/session.ts`) и `can(viewer.access, "tutorials")` (`lib/access-rules.ts`). Нет доступа — покажи бесплатную часть и замок со ссылкой на тарифы, а не пустую страницу. Проверять только в браузере нельзя: cookie ничего не доказывает, решает сервер. В клиентском компоненте того же посетителя даёт `useViewer()` (`lib/viewer.ts`, читает `/api/me`), но лишь для вида — замки на кнопках, подписи.
- **Запуск IDX PACK 3D**: сейчас это заблокированная карточка `features/pack/pack-locked-card.tsx` (размытое содержимое, замок, «Скоро», ссылка на Telegram-канал) внизу `/pricing`. На лендинге её нет. Когда пак выйдет: добавь его тарифом в `content/plans.ts` (и строкой в таблицу сравнения), а карточку убери.

## Отзывы

Все отзывы — в `content/reviews.ts`, в начале файла есть подсказка по полям. Порядок в массиве — порядок на сайте. Показываются в двух местах:

- **«Обо мне»**, карточка «Опыт работы и отзывы»: под строкой клиентов вторая бегущая строка с короткими отзывами (поле `short`, без него — начало текста). Она идёт в другую сторону и медленнее, под курсором останавливается. Справа ссылка «Все отзывы» ведёт к блоку ниже.
- **Блок «Отзывы»** (COMP 05) между FAQ и финальной карточкой: средняя оценка, ссылка «Оставить отзыв» (личка в Telegram) и все отзывы целиком сеткой. Длинная сетка свёрнута до двух рядов с мягким затуханием, «Показать все» плавно раскрывает её, «Свернуть» возвращает. `featured: true` выделяет отзыв тёплой рамкой и кавычкой.

Поля: `name`, `role`, `text`, `short`, `about` (pack, tutorials, resources, assistant, lesson, order), `rating` (1–5), `date` (`ГГГГ-ММ`), `avatar` (файл в `public/reviews/`, без него — инициалы), `link` (где отзыв опубликован), `featured`.

Сейчас в файле 8 примеров с `sample: true`. Они видны только в `npm run dev` и с пометкой «Пример», в продакшен-сборке скрыты, чтобы выдуманные отзывы не попали на сайт. Для демонстрации в сборке — `NEXT_PUBLIC_SAMPLE_REVIEWS=on`. Замени их настоящими и убери `sample`. Если показывать нечего, блок «Отзывы» не выводится, а карточка в «Обо мне» снова называется «Опыт работы с».

## Аккаунты

Три способа войти, каждый включается своими ключами, без них кнопка на `/login` честно говорит, что способ не подключён:

| Способ | Что нужно | Особенности |
| --- | --- | --- |
| Email и пароль | работает всегда | подтверждение адреса и сброс пароля — при настроенном SMTP |
| Telegram | `TELEGRAM_CLIENT_ID`, `TELEGRAM_CLIENT_SECRET` | email не выдаётся, адрес технический |
| Google | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | email приходит уже подтверждённым |

Всё на [Better Auth](https://better-auth.com) (`lib/server/auth.ts`) поверх одного файла SQLite через встроенный драйвер Node (`node:sqlite`): ни сервера баз данных, ни сборки нативных модулей. Пароли хранятся хэшем (scrypt), сессия живёт в базе 30 дней, в браузере — только httpOnly-cookie. Схема поднимается сама при первом запросе: таблицы Better Auth, затем наши.

### Почта

SMTP задаётся в `.env.local` (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`), письма собираются в `lib/server/mail.ts`: подтверждение адреса и сброс пароля, по одной кнопке в каждом. Вёрстка писем — только инлайновые стили и ничего из сети, рядом с HTML всегда текстовая версия. Если SMTP недоступен, ошибка попадёт в лог, но регистрацию не сломает: человек увидит «проверь почту» и сможет попросить письмо снова.

- Пока SMTP не задан, `requireEmailVerification` выключается сам, и аккаунт входит сразу после регистрации. Как только почта появилась, адрес нужно подтвердить до первого входа.
- Ссылки живут час и срабатывают один раз. Устаревшая ведёт на `/verify-email?error=…`, где можно запросить новое письмо.
- Подтверждение само открывает сессию (`autoSignInAfterVerification`), так что второй раз вводить пароль не нужно.
- Домену нужны SPF, DKIM и DMARC, иначе письма уйдут в спам. После настройки проверь доставку в Mail.ru, Яндекс и Gmail: у российских провайдеров свои правила.

### Telegram

Вход сделан на OpenID Connect (старый iframe-виджет с проверкой подписи Telegram убрал в архив), поэтому отдельных роутов и своих проверок в проекте нет: это обычный OAuth-провайдер через плагин `genericOAuth`, redirect-флоу с PKCE и проверкой подписи `id_token`. Сторонние скрипты на страницу не попадают, CSP и COOP ослаблять не пришлось.

Настройка: `@BotFather` → бот → **Login Widget**. Там берутся Client ID и Secret и разрешаются адреса — сам сайт и возврат `<NEXT_PUBLIC_SITE_URL>/api/auth/callback/telegram`. Логин и аватар бота видит человек в окне подтверждения, так что они должны совпадать с сайтом.

- Запрашиваются только `openid` и `profile`. Телефон не просим: это персональные данные, которые нам не нужны.
- Telegram не даёт email, поэтому аккаунт получает технический адрес `tg-<id>@telegram.invalid` (домен `.invalid` зарезервирован RFC 2606 и не может существовать). Письма на такие адреса не отправляются, пароля у такого аккаунта нет.
- Ключ аккаунта — Telegram user id, тот самый номер, который видит бот. Поэтому покупку можно выдать вообще без email (см. ниже).
- Если Telegram не вернёт `nonce` в `id_token`, Better Auth отклонит вход. Тогда в `telegramProvider()` нужно добавить `disableIdTokenNonceBinding: true` — защита от повтора ослабнет, зато вход заработает.
- Локально через `http://localhost` вход не проверить: адреса в BotFather нужны настоящие. Для проверки подойдёт туннель с https.

- **Кто вошёл**: на сервере `getViewer()` (`lib/server/session.ts`) — аккаунт и его доступы, одна проверка на запрос. В браузере `useViewer()` (`lib/viewer.ts`) через `/api/me`.
- **Что открыто**: правила в `lib/access-rules.ts` (`can(access, feature)`), доступы в базе — `lib/server/access.ts`. Таблица `entitlement`: строка на каждую выдачу, у пака конца нет, у подписок период `[starts_at, ends_at)`, продление начинается там, где кончилось предыдущее. Отсюда `tier` (free / lite / pro), `pack` и даты.
- **Лендинг и «Моя студия»**: `src/proxy.ts` смотрит только на cookie и отдаёт на «/» либо статичный лендинг гостю, либо `app/home` вошедшему (адрес тот же). Страница всё равно проверяет сессию по-настоящему, так что просроченная cookie просто вернёт лендинг. Меню для вошедших — `appNav` в `config/navigation.ts`.
- **Админы**: `ADMIN_EMAILS` — у этих аккаунтов открыто всё, без записей в базе.
- **Выдача доступа боту** (`/api/internal/*`, нужен `INTERNAL_API_SECRET` 32+ символа, иначе адреса отвечают 404):

  ```http
  POST /api/internal/grant   Authorization: Bearer <INTERNAL_API_SECRET>
  { "telegramId": "12345678", "plan": "pack" | "lite" | "pro" | "full", "months": 1, "note": "заказ 123" }
  { "email": "user@mail.ru", "plan": "pro", "months": 12 }

  POST /api/internal/promo   Authorization: Bearer <INTERNAL_API_SECRET>
  { "kind": "lite", "months": 3, "maxUses": 1, "expiresInDays": 90 }   → { "code": "IDX-7KQ4-M2XP" }
  ```

  Аккаунт ищется по `telegramId` или по `email`, нужно что-то одно. `telegramId` — то, что бот и так знает про собеседника, так что для вошедших через Telegram ничего спрашивать не надо; email нужен только для тех, кто регистрировался по почте. Аккаунт должен существовать (иначе 404 `user_not_found`): сначала человек заводит профиль на сайте. Промокод посетитель вводит в профиле, каждый код — один раз на аккаунт.
- **База**: файл из `DATABASE_PATH` (по умолчанию `data/ideluxe.sqlite`), в git не попадает. Это единственное, что нужно бэкапить. Режим WAL, поэтому рядом лежат `-wal` и `-shm`. Запросы — только подготовленные, с `?`-параметрами.
- **Куда расти**: оплата на сайте (сумма к списанию должна считаться на сервере), файлы пака за проверкой доступа, защита видео уроков (Kinescope), чеки письмом, напоминание об окончании подписки, возможность добавить настоящий email к аккаунту из Telegram.

## Ресурсы

`/resources` — хаб программ, плагинов и расширений. Слева три раздела: «Программы», «Плагины», «Расширения». У плагинов и расширений под разделом раскрываются группы: «Все», «Модули», «Коллекции» и все плагины по одному (вместе с теми, что внутри коллекций). На телефоне разделы — вкладки сверху, группы — выпадающий список. Справа заголовок раздела, строка фильтров и карточки. Карточка открывает окно позиции: оно раскрывается из самой карточки к центру экрана, иконка перелетает на своё место.

Три вида позиций в «Плагинах» и «Расширениях»:

- **Плагин / расширение** — одна позиция, одна загрузка.
- **Модуль** — несколько плагинов, собранных IDELUXE в одну загрузку (Red Giant, Boris FX, RE:Vision FX). В окне — «Что внутри» со списком.
- **Коллекция** — несколько отдельных позиций под одной карточкой (Video Copilot, AI плагины, Jerry). На сетке она лежит «колодой», в окне — список; каждая позиция открывается в том же окне и скачивается отдельно, «Назад» возвращает к коллекции.

В окне: обложка, название, «Описание»; справа «Разработчик», «Системы», «Доступ», «Совместимость» (нажатие открывает программу) и блок скачивания — выбор версии, если их несколько (у программ годы: 2026 / 2025, у Deep Glow — Deep Glow и Deep Glow 2), выбор системы и кнопка. У программы ниже раскрываются её «Плагины» и «Расширения». Внизу у каждой позиции — «Как установить» по шагам для выбранной ОС (пути копируются кнопкой).

- **Клипы**: под разделами в боковой панели (на телефоне — строкой под вкладками) ссылка «Клипы» на Telegram-канал с клипами, открывается в новой вкладке. Адрес — `site.telegram.clips` в `config/site.ts`; пока там основной канал, замени на канал с клипами.
- **Данные**: `content/resources.ts`. Программы (`programs`) с версиями (`versions`: `id`, `label`, `hint` — номер версии, `downloads`). Плагины и расширения (`addons`): `kind` (`plugin` / `extension`), `mark` (монограмма на иконке, 2–3 знака), `category`, `os`, `license` (это «Доступ»), `site`, `summary` (строка под названием), `about` («Описание»). `contents` делает позицию модулем, `items` — коллекцией. Все плагины и расширения — для After Effects `ADDON_YEAR` (2026), другие программы — `hosts` (Mister Horse, Motion Bro 5, Jerry SFX работают ещё и в Premiere Pro). Несколько вариантов одной позиции — `builds`, у каждого свои `downloads`. Порядок в массивах — порядок «Популярные». Словарь разделов, видов, категорий и подписей — `content/resource-taxonomy.ts`.
- **Ссылки на скачивание**: `downloads: { win, mac }` — у версии программы, у варианта (`builds`) или прямо у позиции, если вариант один. Без ссылки кнопка ведёт на сайт разработчика (`site`), без сайта — «Ссылка появится скоро». Сейчас ссылок нет нигде.
- **Установка**: шаги собираются по шаблону из `setup` (`installer` — установщик, `module` — установщик модуля, `manual` — копирование в общую папку плагинов Adobe, `zxp` — пакет через ZXP Installer, `panel` — панель ScriptUI). Свои шаги — поле `install`.
- **Доступ** (`lib/access-rules.ts` → `canOpenResource`): с IDX LITE / PRO и у админов открыто всё, в бесплатном аккаунте — программы и позиции с `free: true`, без аккаунта — ничего. Смотреть каталог могут все, но прямые ссылки сервер кладёт в страницу только для открытых этому аккаунту позиций (`features/resources/catalog.server.ts`, поля копируются по белому списку). `content/resources.ts` помечен `server-only`, в браузер он не попадает. В бесплатном режиме на закрытых позициях замок и переключатель «Только открытые», гостю — подсказка, что откроется с аккаунтом.
- **Фильтры**: поиск по разделу (горячая клавиша «/»; ищет по названию, разработчику, описанию, категории, программам и составу модулей — найденное внутри модуля подписано на карточке; позиции из коллекций находятся по одной), «Программа» (только если позиции раздела работают в нескольких программах), система, порядок. Если в разделе по запросу пусто, а в другом нашлось, это сразу предлагается. Систему браузер запоминает (`prefs.ts`). Ссылки `?s=plugin` (раздел) и `?r=<id>` (окно позиции) можно отправить.
- **Анимации**: карточки появляются вместе со страницей (`arrive`), после смены раздела или фильтра — коротким проявлением. Окно раскрывается из карточки и складывается обратно в неё, шаг внутрь и «Назад» сдвигают содержимое вправо и влево (`item-dialog.tsx`, `resources.css`). При «Уменьшить движение» всё сразу на месте.

## Туториалы

`/learn` — каталог разборов. Слева разделы из `content/tutorial-categories.ts` (VFX, SFX, Motion, Переходы, Цвет, Экспорт) и «Все разборы», у вошедшего рядом счёт «просмотрено/всего». На телефоне разделы — ряд чипов с прокруткой. Над карточками поиск («/»), «Программа», «Просмотр» (не начатые / начатые / просмотренные, только с аккаунтом), «Только открытые» (бесплатный режим и гости) и порядок: по порядку, новые, короткие. Если что-то недосмотрено, сверху «Продолжить просмотр». Ссылка `/learn?s=vfx` открывает раздел, на неё ведут чипы блока «Платформа» на лендинге.

Карточка: обложка 16:9 с длиной, «Новое» (первые `NEW_DAYS` = 21 день), «Бесплатно» или «PRO», полоса прогресса и галочка у просмотренного. Ниже раздел, число глав, название, строка о разборе и программы.

Страница урока `/learn/<slug>`:

- **Плеер** (`player.tsx`) в стиле монитора программы. Свет видео разливается вокруг окна. Таймлайн с линейкой, главы на нём — ромбики ключей с разрывами в полосе, при наведении видно время и главу. Есть −10 / +10 с, звук, скорость 0,75–2× (запоминается), качество, «картинка в картинке» и полный экран. До первого запуска поверх лежит обложка, а если урок начат — «Ты остановился на 4:12 · Продолжить / Сначала». В конце: «Разбор просмотрен», следующий урок раздела и «Ещё раз». Клавиши физические, работают и в русской раскладке: Space / K, J / L ±10 с, ← / → ±5 с, ↑ / ↓ громкость (в плеере), M, F, 0–9, Shift + < / > — скорость.
- **Главы** справа от плеера (на десктопе ровно его высоты): текущая подсвечена и следует за видео, клик — переход.
- Под плеером название, длина, главы, программы и кнопки: «Отметить просмотренным», «Спросить ассистента» (чат открывается с вопросом про этот разбор). Дальше «О разборе», «Что понадобится» (ссылки на позиции «Ресурсов», `/resources?r=<id>`) и файлы урока. Справа список раздела с прогрессом.

**Доступ** (`lib/access-rules.ts` → `canWatchTutorial`): с IDX PRO и у админов открыты все уроки. В бесплатном аккаунте (и с LITE) — вводные (`intro: true`), без аккаунта — ни один. Каталог и страницы видны всем: закрытый урок показывает, о чём он, главы и что его откроет. Гостю — «Создать аккаунт / Войти» с возвратом на этот урок (`?next=`, принимается только путь на этом сайте), бесплатному — «Открыть PRO». Ссылки на видео и файлы сервер кладёт в страницу только для открытых этому аккаунту уроков (`features/learn/catalog.server.ts`, поля копируются по белому списку), `content/tutorials.ts` помечен `server-only`.

**Прогресс** (`features/learn/progress*.ts`, таблица `tutorial_progress`): плеер сообщает позицию каждые 15 с просмотра, на паузе, после перемотки, в конце, при скрытии вкладки и уходе со страницы. Урок считается просмотренным с 90 %, отметку можно поставить и снять руками. `POST /api/learn/progress` принимает запросы только со страниц сайта и только от вошедшего аккаунта, для существующего и открытого ему урока. Тело до 1 КБ, числа проверяются, на аккаунт до 6000 отчётов в день. В профиле из того же прогресса собраны «Достижения»: сколько просмотрено, серия дней подряд с досмотренным разбором (по Москве), пройденные разделы и «Продолжить». На «Моей студии» плитка «Туториалы» показывает «Просмотрено» и ведёт к недосмотренному.

**Данные** — `content/tutorials.ts`, порядок в массиве = «По порядку»:

- `slug` — адрес и ключ прогресса, у опубликованного урока не меняй;
- `section`, `title`, `summary` (строка на карточке), `about` (абзацы через пустую строку), `intro`;
- `duration` — секунды, `published` — `ГГГГ-ММ-ДД`, `programs` — `ae`, `pr`, `me`, `ps`, `vg`;
- `chapters` — `{ at: секунды, title }`, `resources` — id из `content/resources.ts`, `files` — `{ label, href, size }`;
- `poster` — своя обложка 16:9. Без неё обложка рисуется из цвета раздела и его 3D-объекта (`tint`, `decor` в `tutorial-categories.ts`), поворот и место объекта зависят от `slug`;
- `video` — `renditions` (`label`, `src`, `minWidth`, лучшее качество первым), `aspect`.

**Сейчас** в каталоге 16 примеров, по 2–4 на раздел, по одному вводному в каждом. Видео у всех — заглушка: шоурил (`demo()` и `DEMO_VIDEO`), главы для плеера ужаты под его 57 секунд, на видео подпись «Демо-ролик вместо урока». Когда появятся настоящие уроки, впиши их и убери `demo()`.

**Защита видео** — на стороне хостинга: уроки переедут в Kinescope (шифрование и DRM, водяной знак с аккаунтом зрителя, подписанные ссылки, привязка к домену). Тогда у урока в `video` вместо `renditions` будет его id в Kinescope, а плеер начнёт брать поток оттуда. Пока сервер отдаёт ссылку на видео только тем, кому урок открыт, но сама ссылка ничем не защищена.

### Эдиты

Лента во вкладке «Шоурил эдитов» берёт ролики из `content/edits.ts` (инструкция в начале файла), файлы — из `public/videos/edits`. Порядок в массиве = порядок в ленте и на таймлайне.

- Карточки листаются свайпом или перетаскиванием, горизонтальным жестом тачпада, стрелками, кликом по соседней карточке, по списку «Проект · Эдиты» или по таймлайну: эдиты стоят на нём подряд, как клипы, и перемотка переключает ролики. Доиграл — включается следующий. Клик по текущей карточке открывает её со звуком в плеере, который вылетает из карточки.
- Пока на вкладку не навели курсор, ничего не грузится; после наведения — обложки, после открытия — видео, и только у текущей карточки и двух соседних. Без звука, на паузе вне экрана, под плеером и во время перехода; при «Уменьшить движение» лента стоит, пока не нажмёшь ▶.
- «Ещё эдиты в Telegram» ведёт на `site.telegram.clips` (`config/site.ts`), тот же канал, что «Клипы» в «Ресурсах».
- Сейчас там демо: шесть вертикальных нарезок из `showreel-1080.mp4`. Свои эдиты сжимай так (ролик и обложка 540×960, обложка — кадр на 2-й секунде):

```bash
ffmpeg -i edit.mov -vf "scale=540:960:force_original_aspect_ratio=increase,crop=540:960,setsar=1" -c:v libx264 -preset slow -crf 25 -profile:v high -pix_fmt yuv420p -g 48 -c:a aac -b:a 128k -movflags +faststart public/videos/edits/name.mp4
ffmpeg -i public/videos/edits/name.mp4 -ss 2 -frames:v 1 -q:v 4 public/videos/edits/name.jpg
```

## Космический фон

`features/backdrop`: фиксированный слой за всем сайтом.

- Звёзды и редкий метеор — `starfield.ts` (canvas 2D).
- Планета — `planet.ts` и `planet-shaders.ts` (WebGL 1). Солнце спрятано за ней: светится тонкий серп у края и атмосфера (голубая, у солнца переходит в золото), остальное ночная сторона с огнями городов. Край — мягкая полоса в несколько пикселей, а не яркая линия. Фон остаётся тёмным, текст поверх читается. Карта поверхности (материки, облака, города) считается один раз при загрузке, по полосам за несколько кадров. Дальше каждый кадр — две выборки из текстуры на пиксель, и только в тех строках экрана, где есть планета и её свечение.
- Вращение (`space-scene.tsx`): в покое планета медленно крутится сама (`IDLE_SPIN`). Прокрутка вниз разгоняет её в ту же сторону, вверх — крутит назад с той же скоростью (`SCROLL_SPIN`, предел `MAX_SPIN`). Скорость сглажена (`SPIN_RESPONSE`), после прокрутки планета плавно возвращается к своему ходу. Облака идут чуть быстрее поверхности.
- Камера (`camera.ts`): у каждой страницы свой кадр. На лендинге край планеты поднимается снизу. На «Тарифах» камера облетает планету, и она висит справа, на «Ресурсах» — слева, серп света развёрнут к контенту. На входе камера поднимается над планетой, остаётся только космос. При переходе камера летит между кадрами: планета идёт по дуге, звёзды сдвигаются с параллаксом и смазываются, мимо проносится космическая пыль. Кадры — `shotPose`, страницы → кадры — `shotFor`, длительность и дуга полёта — `planFlight`.
- Появление страницы привязано к полёту. Блоки с классом `arrive` начинают выплывать из глубины на 28 % полёта (`ARRIVE_START`) и встают на место к 90 % (`ARRIVE_END`), вместе с камерой, смещаясь в ту же сторону, что и звёзды. `SpaceScene` задаёт переменные `--arrive-delay`, `--arrive-duration`, `--arrive-x`, `--arrive-y` маленькой таблицей стилей прямо для `.arrive` / `.decor-in` (переменные не наследуются, `@property` в `styles/animations.css`) и после посадки сбрасывает их. Длительность полёта: на лендинг и на «Тарифы»/«Ресурсы» 2,05–2,5 с, на вход 2 с, первый после прелоадера 2,8 с.
- Огни городов запечены в карту поверхности (канал B): скопления небольших пятен вдоль побережий. При вращении они не мерцают. Яркость и цвет — в `PLANET_FRAG`, рисунок — в `SURFACE_FRAG`.
- Детализация: на экранах от 1200 px карта поверхности 4096×2048 (2048 на остальных десктопах, 1024 на телефонах), 8 октав шума, горные хребты. В кадре есть рельеф: склоны ловят низкое солнце у терминатора. Ещё полярные шапки, равнины и пустыни разного цвета.
- Экономия: пока ничего не движется (нет полёта, прокрутки, движения курсора), фон рисуется ≈30 кадров/с, в движении — не меньше 60 (`IDLE_FPS` / `BUSY_FPS`). Кадры отсчитываются обновлениями экрана, а не миллисекундами, поэтому шаг ровный: на 144 Гц в движении каждое 2-е обновление (72 кадра/с), на 60 Гц каждое. Каждый кадр фона заставляет все видимые стеклянные панели заново размывать то, что за ними, так что это заметно разгружает видеокарту. Редактор на первом экране обновляется не чаще 60 раз в секунду, а во время полёта (`data-flying`) не считает скопы.
- Что ещё настраивается в `planet.ts`: наклон оси `TILT`/`ROLL`, направление на солнце `SUN`. Цвета и яркость — в `PLANET_FRAG`.
- Без WebGL рисуется плоский силуэт с ореолом, при «Уменьшить движение» — один неподвижный кадр, страницы переключаются без полёта. Пока открыт плеер шоурила, анимация стоит (`lib/video-hold.ts`).

## Прелоадер

`features/preloader` (`boot-script.tsx`, `preloader.tsx`, стили — блок «Preloader» в `styles/components.css`). При первой загрузке вкладки: знак IDX рисуется линиями, под ним «рендер» — таймлайн с плейхедом, процент и таймкод. Ждёт шрифты, загрузку страницы и первый кадр планеты (не меньше 1,5 с, не больше 7 с). Потом из центра раскрывается «диафрагма», знак улетает в камеру, стартуют анимации появления, а камера опускается и поднимает планету в кадр (`lib/boot.ts`).

- Встроенный скрипт ставит `html[data-boot]` до первой отрисовки. Пока атрибут стоит, прелоадер виден, страница не прокручивается, анимации `animate-fade-up` / `fade-in` / `rise-in` ждут.
- Перезагрузка в той же вкладке — короткая версия (0,5 с, `sessionStorage`). Переходы по сайту прелоадер не показывают.
- Без JavaScript прелоадера нет. Если скрипты не загрузились, через 10 с страница открывается сама.

## 3D-декор

Объекты по бокам — заранее отрендеренные прозрачные WebP из `public/decor` (17–45 КБ), WebGL ради них в браузере не запускается. Набор: `play`, `keyframe` (ключ After Effects), `lens`, `wave` (звук), `sparkle` (иконка ассистента) и абстрактные `knot`, `cube`, `asterisk`. Все восемь рендерит `tools/decor-render` с общим светом под фон: тёплый контровой сверху-сзади, как золотое солнце за планетой, шампань слева, холодная сталь справа, слабый голубой отсвет атмосферы снизу. Материалы — небольшой «продуктовый» набор: чёрный хром, матовое шампань-золото, айвори-керамика, перламутр.

Каждый объект парит (два цикла `levitate` и `sway`) и живёт в глубине кадра (`features/decor/decor-3d.tsx`):

- `depth` ≈ 0.6 — плоскость фокуса, где контент: объект резкий.
- Меньше — дальше за контентом: мельче по параллаксу, размыт, тусклее и серее.
- Больше 0.85 — передний план. Объект рисуется поверх контента, сильно размыт и затемнён, держится у края экрана и не заходит на колонку текста. Показывается только на экранах от 1280 px.
- Ближние объекты обгоняют прокрутку, дальние отстают. У верхнего края все немного теряют фокус.

Объекты появляются по очереди вместе со страницей (`.decor-in`). Пасхалка: если провести курсор рядом, объект немного тянется к нему, а когда курсор уходит, отцепляется и пружинит на место (`MAGNET_*` в `decor-3d.tsx`, только мышь, не при «Уменьшить движение»).

Расстановка: объекты есть только на первом экране лендинга (четыре штуки вокруг заголовка и окна редактора, `features/landing/decor.ts`). В остальных блоках и на внутренних страницах их нет, и это решение заказчика: новые туда не добавляем. Параметры объекта: сторона и отступ `x` (отрицательный — частично за краем), `inset` (сдвиг к контенту на широких экранах), `size`, `rotate`, `depth`, `blur` (вместо размытия по глубине), `mobile`.

### Перерендер и новые объекты

Модели, материалы и студийный свет — в `tools/decor-render/scene.js` (three.js). Рендер идёт в headless Edge (или Chrome через `BROWSER_PATH`), у инструмента свои зависимости, в сайт они не попадают:

```bash
npm install --prefix tools/decor-render
npm run render --prefix tools/decor-render              # все объекты
npm run render --prefix tools/decor-render -- play lens # выборочно
```

Скрипт пишет `public/decor/<name>.webp` и `tools/decor-render/preview.png` (все объекты на фоне сайта), а в консоль выводит размеры. Новый объект: функция в `objects` в `scene.js`, затем имя и размер в `DecorName` и `DECOR_SIZE` (`features/decor/assets.ts`). После перерендера увеличь `DECOR_VERSION` там же: браузеры держат `/decor` в кэше неделю.

Их несёт сама планета: каждый кадр точка земли под ёлкой проходит вращение (`planetGeometry` в `backdrop/planet.ts`, те же матрицы, что у шейдера) и возвращается на горизонт. Промежутки между ними чуть меньше видимой на десктопе дуги, так что в кадре всегда есть хотя бы одна; первая стоит на поле слева от контента уже на первом экране;

**Убрать насовсем**: удали `features/new-year`, `public/decor/new-year` и `tools/decor-render/new-year.js`, затем места подключения — они помечены комментарием `New Year theme`, а TypeScript покажет оставшиеся импорты: `site-shell.tsx`, `header.tsx`, `footer.tsx`, `icons.tsx`, `features/landing/decor.ts`, секции лендинга `hero`, `about`, `platform`, `auth/auth-card.tsx`, `pricing/plan-cards.tsx`, `chat/chat-widget.tsx`, `resources/sidebar.tsx`, `learn/sidebar.tsx` и две строки в `tools/decor-render/scene.js`. ## ИИ-ассистент

Окно чата вырастает из кнопки в правом нижнем углу и сворачивается обратно в неё (класс `pop-panel` в `styles/components.css`). Закрывается той же кнопкой, клавишей Escape или кликом в любом месте страницы, кроме кнопок «Спросить ассистента» (`OpenChatButton`). Кнопка всегда стоит на месте в углу, в том числе в самом низу страницы. Там, где карточка футера уходила бы под неё (экраны уже ≈1330 px), футер оставляет пустую полосу снизу.

Любой OpenAI-совместимый API, по умолчанию DeepSeek. Ключ и модель — в `.env.local` (см. `.env.example`). Промпт собирается в `features/chat/system-prompt.ts` из `content/*` и `config/site.ts`: роль, стиль, границы тем, запрет помощи со взломом ПО.

Ассистент открывается с IDX PRO: гостю `/api/chat` отвечает 401, аккаунту без подписки — 403, и виджет вместо переписки показывает замок со ссылкой на тарифы. Остальная защита: запросы принимаются только со страниц самого сайта (Origin или `Sec-Fetch-Site: same-origin`, без них — 403). Размер тела считается по мере чтения (64 КБ). Есть лимиты на число и длину сообщений и на общий объём (8000 символов), история не может начинаться с выдуманного ответа ассистента. Дневные лимиты: на аккаунт (`CHAT_USER_DAILY_LIMIT`), на IP (`CHAT_DAILY_LIMIT`, несколько аккаунтов за одним адресом) и на весь сайт (`CHAT_GLOBAL_DAILY_LIMIT`, потолок расходов на API). IP берётся из `X-Forwarded-For` справа, от доверенного прокси (`TRUSTED_PROXY_HOPS`, по умолчанию один nginx). Без прокси перед сайтом заголовок можно подделать, поэтому деплой — только за ним. Лимит считается в памяти процесса: подходит для одного сервера (`npm start` на VPS). На serverless или нескольких инстансах счётчики не общие и сбрасываются при перезапуске, поэтому до публичного запуска счётчик нужно перенести в общее хранилище (Postgres, Redis) за тем же интерфейсом `consumeDailyQuota`. Дефолтную модель `AI_MODEL` (`deepseek-flash`) сверь с актуальным списком моделей провайдера.

## Безопасность

- Заголовки (`next.config.ts`): `X-Frame-Options: DENY`, COOP/CORP, `Permissions-Policy`, `nosniff`. В продакшене ещё CSP и HSTS (сайт должен работать по HTTPS).
- CSP запрещает чужие скрипты, фреймы, плагины, формы на сторонние адреса и `<base>`. Для скриптов разрешён `'unsafe-inline'`: Next встраивает данные страницы прямо в HTML, а прелоадер ставит маленький встроенный скрипт. Строгая политика с nonce (`src/proxy.ts` + nonce в `layout.tsx`) возможна, но тогда все страницы станут динамическими.
- Форма входа отправляется методом POST, поэтому даже до загрузки JS пароль не попадёт в адресную строку. История чата из `localStorage` проверяется при загрузке, на сервер уходят только последние 12 сообщений. Если страница упала, `app/error.tsx` показывает «Повторить», а если упал корневой макет — `app/global-error.tsx`.
- Аккаунты: пароли — хэш scrypt (Better Auth), сессия в базе, в браузере httpOnly-cookie (`Secure` на https), минимум 8 символов. Запросы к `/api/auth/*` ограничены по IP (`X-Real-IP` от nginx; `X-Forwarded-For` клиент может подделать): вход — 5 попыток в минуту, регистрация — 5 за 10 минут. Принимаются только со своего адреса (`trustedOrigins` = `NEXT_PUBLIC_SITE_URL`), поэтому в продакшене переменную нужно задать правильно. `BETTER_AUTH_SECRET` короче 32 символов в продакшене роняет запрос, а не тихо работает.
- Подтверждение адреса — не формальность: доступ выдаётся по email, и без проверки можно было бы занять чужой адрес и перехватить подписку, которую его настоящий владелец позже купит через бота. Поэтому с настроенной почтой вход до подтверждения закрыт. Ответ на запрос сброса пароля не зависит от того, есть ли такой аккаунт, а ссылки из писем живут час и срабатывают один раз; после смены пароля остальные сессии закрываются.
- Права проверяет сервер: страницы через `getViewer()`, `/api/chat` — до обращения к модели, `/api/learn/progress` — до записи (свой аккаунт, открытый ему урок, проверенные числа). Видео и файлы закрытых уроков в страницу не попадают. Возврат после входа (`/login?next=…`) принимает только путь на этом сайте: `//host`, обратные слэши и чужие адреса отбрасываются, вход ведёт на «/». Клиентский `useViewer()` рисует замки, но ничего не решает. `/api/internal/*` сверяет Bearer-токен за постоянное время и без секрета 32+ отвечает 404. Страницы аккаунта закрыты от индексации (`robots: noindex`).
- Что остаётся сделать перед приёмом денег: оплата со сверкой суммы на сервере, выдача файлов пака за проверкой доступа (сейчас пак отдаёт бот), защита видео уроков (Kinescope), бэкап базы. В dev-зависимостях `npm audit` показывает уязвимость `braces` внутри `eslint-config-next` — только для линтера, в сборку сайта не попадает.

## Чего пока нет

Готовы лендинг, тарифы и аккаунты с правами доступа. Готов каталог «Ресурсы» (прямые ссылки на скачивание пока не вписаны, кнопки ведут на сайты разработчиков). Готова платформа туториалов: каталог, страница урока с плеером, прогресс и достижения в профиле. Настоящих уроков пока нет: в каталоге 16 примеров с шоурилом вместо видео (см. «Туториалы»). Проверено на продакшен-сборке с отдельной базой, на 1440 и 390 px: гость, бесплатный аккаунт и админ видят свои замки; гостю и бесплатному аккаунту ссылки на видео закрытых уроков в страницу не попадают (гостю — и вводных); плеер (главы, скорость, клавиши, конец урока), сохранение позиции и «Продолжить» после перезагрузки, отметка «Просмотрено», «Продолжить просмотр» в каталоге, «Достижения» и плитка на «Моей студии»; `/api/learn/progress` отвечает 401 гостю, 403 без Origin, с чужим Origin и на закрытый урок, 404 на неизвестный, 400 на плохие числа, 413 на большое тело; вход с `?next=` возвращает на урок, а `?next=//чужой-адрес` ведёт на «/». Оплаты на сайте нет — все кнопки покупки ведут в Telegram-бота, он же выдаёт доступ через `/api/internal/grant`. Юридические документы — заглушки «В работе»; текст оферты про подписку и возвраты нужно проверить с юристом.

Вход через Telegram и Google написан, но на реальных ключах не проверялся: для Telegram нужен настоящий https-домен в BotFather, для Google — OAuth-клиент. Без ключей оба способа выключены на сервере, и кнопки это сообщают.

Проверено: `lint`, `typecheck`, `build`; в браузере на 1440×900 и 390×844 — все блоки лендинга, плеер шоурила (пауза фона при открытом плеере), мобильное меню, тарифы с переключателем и таблицей. Первый экран — на 1280×800 … 2560×1440. Переходы главная ↔ тарифы ↔ вход и CSP — на продакшен-сборке (`next start`): нарушений CSP нет, кадры при переходах ≈7 мс (144 Гц), без провалов. Аккаунты — на продакшен-сборке с отдельной базой: регистрация, вход, неверный пароль, выход, повторный вход; лендинг гостю и «Моя студия» вошедшему на одном адресе; `/profile` гостя уводит на вход; чат отвечает 401 гостю, 403 на free и 200 с PRO; промокод (неверный, успешный, повторный); выдача `pack`/`lite`/`pro`/`full` ботом, 401 с чужим секретом и 404 на незнакомый email.

Почта — на продакшен-сборке с локальным SMTP-приёмником: письма уходят с обеими частями (текст и HTML) и верными темами; регистрация ждёт подтверждения и не создаёт сессию; вход до подтверждения присылает письмо снова; ссылка подтверждает адрес и сразу открывает сессию; повторный переход по ней даёт «ссылка устарела» с запросом нового письма; сброс пароля — письмо, смена, старый пароль перестаёт работать, ссылка больше не срабатывает. Кнопки Telegram и Google без ключей остаются на странице и показывают подсказку. Экраны писем и нового пароля проверены на 1440 и 390 px.
